# Гайд по администрированию ovpn-admin

Короткая инструкция для тех, кому передали уже настроенный сервер.

---

## 1. Включить MFA на свой аккаунт

Сразу после первого логина — **обязательно**.

1. Profile → **MFA Setup**
2. Отсканируй QR-код в **Authy** или **Google Authenticator**
3. Сохрани **backup-codes** в менеджер паролей (не в чат, не в текстовый файл на рабочем столе)

Без этого защита админки держится только на пароле — если он утечёт, доступ к серверу будет у любого.

---

## 2. Добавить клиента

**Users → «+ Добавить»**

- Имя только латиницей, без пробелов и спецсимволов (разрешены `_`, `.`, `-`, `@`, до 63 символов).
- Сертификат выпускается автоматически.
- Скачай `.ovpn`-файл (зелёная иконка скачивания) → передай юзеру → импорт в клиент.

### Клиентские приложения

Что качать пользователю в зависимости от устройства:

| ОС | Рекомендую | Альтернатива |
|---|---|---|
| **macOS** | [OpenVPN Connect](https://openvpn.net/client/client-connect-vpn-for-mac-os/) — официальный, проще для нетехнических | [Tunnelblick](https://tunnelblick.net/) — open-source, больше настроек |
| **Windows** | [OpenVPN Connect](https://openvpn.net/client/client-connect-vpn-for-windows/) — официальный | [OpenVPN Community](https://openvpn.net/community-downloads/) — open-source, без UI-обёртки |
| **iPhone / iPad** | [OpenVPN Connect (App Store)](https://apps.apple.com/app/openvpn-connect/id590379981) — единственный нормальный вариант | — |
| **Android** | [OpenVPN Connect (Google Play)](https://play.google.com/store/apps/details?id=net.openvpn.openvpn) | [OpenVPN for Android (Arne Schwabe)](https://play.google.com/store/apps/details?id=de.blinkt.openvpn) — open-source |
| **Linux** | Системный `openvpn` пакет (`apt install openvpn` / `dnf install openvpn`) + NetworkManager-OpenVPN GUI | — |

**Импорт `.ovpn` файла**:
- OpenVPN Connect: drag-and-drop файл в приложение, либо «Import → File»
- Tunnelblick: двойной клик на `.ovpn` файле, согласиться установить
- iPhone/iPad: открыть `.ovpn` через AirDrop/Mail/Files → «Открыть в OpenVPN»
- Android: открыть из файлового менеджера → выбрать OpenVPN Connect

## 3. Маршрутизация (два уровня)

### Общие маршруты — для **всех** пользователей

**Server → Общие маршруты**

Применяются к каждому подключённому клиенту. Пример: корпоративная подсеть `10.0.0.0/24`, рабочие сервисы.

### Персональные маршруты — для **одного** пользователя

**Users → юзер → «Маршруты»**

Только этот клиент будет получать.

### Импорт из файла

И в общих, и в персональных есть кнопка **«Импорт»**. Одна строка — одна запись:

```
# комментарии игнорируются
example.com           # домен (резолвится автоматом)
10.0.0.0/24           # CIDR
1.2.3.4 255.255.0.0   # IP + маска
8.8.8.8               # bare IP → /32
```

После импорта показывается отчёт: сколько добавилось, сколько пропущено как дубль, какие строки не прошли валидацию.

## 4. Режим VPN: split vs full tunnel

| Режим | Что идёт через VPN | Когда использовать |
|---|---|---|
| **Split-tunnel** (по умолчанию) | Только маршруты из «Общих» + «Персональных» | Обычный сценарий: доступ к корпоративной сети, отдельным сервисам |
| **Full-tunnel** | Весь трафик клиента | Полная анонимность, обход блокировок, замеры скорости |

Переключение: **Server Config → ☑ redirect-gateway def1 → Save**. Изменение применяется автоматически — клиенты переподключаются с новым push.

### DNS

**Server Config → DNS-серверы**. Рекомендуемые:
- `1.1.1.1` (Cloudflare)
- `8.8.8.8` (Google)

DNS пушится клиенту вместе с маршрутами. Если хочешь чтобы клиент использовал свой локальный DNS — оставь поле пустым.

---

## 5. Авто-обновление маршрутов

Доменные маршруты резолвятся автоматически:
- **При сохранении** — синхронно
- **Периодически** — каждые `domain_refresh_interval_hours` часов (по умолчанию 24, настраивается в Server Config; 0 = отключено)
- **Вручную** — кнопка «Обновить DNS» в общих маршрутах и в персональных

Если IP домена сменился — затронутые клиенты автоматом переподключаются и получают новые маршруты.

## 6. Управление клиентами

| Действие | Что происходит |
|---|---|
| **Отозвать** | Cert в CRL, активная сессия рвётся, переподключиться нельзя. **Можно вернуть** через «Восстановить» |
| **Удалить** | Cert в CRL, файлы стираются, активная сессия рвётся. **Восстановить нельзя** — нужно создавать заново |
| **Задать / Сменить / Убрать пароль** | Доступно, когда в табе **Сервер** включена «Парольная аутентификация». Юзер с паролем (значок 🔑) заходит по **сертификату + паролю**; «Убрать пароль» возвращает его в режим «только сертификат» |
| **Маршруты** | Редактировать персональные push'ы для этого юзера |

Все мутирующие действия требуют MFA-код в этой сессии.

### Пароль на VPN-подключение (для отдельных юзеров)

По умолчанию клиенты ходят **только по сертификату**. Если нужно «второй фактор» для критичных аккаунтов:

1. Таб **Сервер** → включить тумблер **«Парольная аутентификация»** (добавляет на сервер `auth-user-pass-optional`, openvpn перезагружается).
2. Таб **Пользователи** → у нужного юзера «⋯» → **«Задать пароль»**.

Тогда у этого юзера в `.ovpn` появляется `auth-user-pass` и при подключении спрашивается логин/пароль; **остальные подключаются без запроса**. Проверяет пароль сам openvpn (через `auth.sh` → `openvpn-user` → `users.db`), так что VPN работает даже если панель недоступна.

### Трафик

Таб **Трафик** показывает, сколько каждый юзер передал — **помесячно** (с выбором месяца и колонкой «за всё время»). Счётчики продолжаются после реконнектов и переживают рестарт (если state-dir на durable-хранилище).

## 7. Что делать НЕ надо

- ❌ Не светить админский пароль и backup-codes в чатах/гитах/скриншотах
- ❌ Не использовать `:latest` тег у docker-образов — только конкретные версии (`v2.0.12` и т.д.)
- ❌ Не оставлять отозванных юзеров с активными сертами — раз в полгода аудит
- ❌ Не выставлять docker management-port наружу
- ❌ Не выключать MFA в Server Config, если есть несколько админов

## 8. Что-то не работает

### Speedtest показывает не VPN-IP

Speedtest использует CDN с динамическими IP. Для замера через VPN временно включи **full-tunnel** (`redirect-gateway def1` в Server Config).

### Клиент подключился, но сайт не открывается

- Включён ли push DNS? Без него клиент может пытаться резолвить через приватный DNS своей домашней сети
- Проверь что маршрут добавлен для **правильного домена** (с/без `www` — разные IP на CDN)

### Кикнул юзера — он снова подключается со старым `.ovpn`

Используй **«Удалить»** или **«Отозвать»** в админке, а не просто разлогинить. Это добавит cert в CRL и сервер откажет в подключении.

### Сертификаты выпускаются с ошибкой `Failed to create lock-file`

Проблема с правами на `easyrsa/pki/`. На бэкенде:

```bash
chgrp -R 2000 /var/lib/ovpn-admin/easyrsa
chmod -R g+rwX /var/lib/ovpn-admin/easyrsa
```

## 9. Обновление до новой версии

Для крупного апгрейда (напр. **2.0.19 → 2.0.35**) есть отдельный гайд с шагами,
чек-листом и объяснением миграции состояния: [`docs/UPGRADE.md`](UPGRADE.md).

В корне репозитория есть git-теги вида `v2.0.X`. После выхода новой:

```bash
ssh root@<твой-бэкенд>
cd /opt/ovpn-admin
sed -i 's/:2\.0\.X/:2.0.Y/g' .env  # подставь свои версии
docker compose pull
docker compose up -d              # depends_on правильно поднимет в порядке
```

Никакого `down -v` — это удалило бы named-volume и сбило бы рендер `server.conf` (хотя он перерендерится при следующем старте, лучше не рисковать).

**MFA и сессии при обновлении сохраняются.** Состояние авторизации (MFA-регистрация, ключ подписи сессий, чёрный список логаутов, API-токены, история трафика) живёт в **state-dir**. При апгрейде со старых версий, которые держали его рядом с htpasswd, ovpn-admin при первом старте сам переносит файлы в настроенный state-dir (не перезаписывая) — админа не залочит, 2FA не слетит. Главное — чтобы state-dir был на durable-хранилище (bind-mount/PVC), а не в эфемерном слое контейнера.
